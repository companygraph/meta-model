# Role Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `role` to CompanyGraph core, give `profile` a `nature` and the `roles` it holds, ship the first enum check, release 0.23.0, and write the reference instance's five roles and its agent profile.

**Architecture:** One new file type, `role`, owned by nothing, shaped from the family's own writer and translator rulebooks: what it takes, what it produces, what it never does, plus the skills it `requires`. The profile gains a required `nature` enum (`human` or `agent`) and an optional `roles` list; the edge points from the profile to the seat. R8 gains the form an enum's Description takes so a check can read the values, and the instance checks gain that check. The parser needs no change: `requires` and `roles` are references it resolves by declared type, and `nature` is a fact.

**Tech Stack:** Markdown, Node 22's built-in test runner, `npm run verify` and the three `npm run test:*` suites in `companygraph/meta-model`, the instance checker at the release tag, `npm run model` in `robertblust.github.io`, `npm run build` in `companygraph.github.io`.

**Spec:** `docs/superpowers/specs/2026-09-15-role-design.md`

## Global Constraints

- Core and the package are both at 0.22.0 and **both go to 0.23.0**. The version string lives in `core/manifest.json`, `package.json`, and twice in `.github/workflows/instance-check.yml` (the `ref:` and the example `uses:` in the header comment). All four move together. `shape` stays **2**.
- The field on profile is **`nature`**, values **`human`** and **`agent`**, required. Never `kind`: the parser stamps any entity whose `kind` is set as a period label.
- The role's frontmatter is `source`, `source-id`, `requires` (optional, `array of ref → skill`). Its sections are `# [Seat]`, `> [Purpose]`, `## What it takes`, `## What it produces`, `## What it never does` (all three required), `## References` (optional, Table with `What` and `URL`).
- The profile gains `roles` (optional, `array of ref → role`). The edge points from the profile. **A role file never names who holds it.**
- **The gap rule.** A skill a role requires that the holder does not claim is reported by the validation pass, never a failure. The mechanical checker stays out of it.
- An enum field's Description opens with its values as backticked tokens: `` `human` or `agent`. `` The R8 check reads tokens off the front of that cell.
- Core is company-generic. Nothing in `core/` or `example/` names Robert Blust, blust.ch, Claude or any real product. The example's agent is named `AI Agent`, which is generic by design.
- **The multi-person instance is never named** in any file, commit message or pull request description.
- Prose follows `conventions/WRITING.md`: American English, spaced em-dashes, sentence case in headings, no serial comma, curly quotes. Run `sh conventions/conventions-check` before every commit. `docs/superpowers/` is excluded from that check.
- Every commit runs the checks its task names and is made only when they pass. Check exit codes on their own.
- Commit messages follow the git register: subject under seventy characters, no type prefix, no trailing period; one to three short paragraphs, cause before mechanism; one line beginning `Verified:`; then the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and nothing else.
- Pull request descriptions are the commit body reread for a reviewer, plus sibling links, ending with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. **No Summary/Test-plan template.**
- **Nothing is merged and nothing is tagged by an agent.** Each phase ends with a green pull request and stops.
- Phase 2 is blocked until Phase 1 is merged and tagged `v0.23.0`. Phase 3 is blocked until Phase 2 is merged. Phase 4 is blocked until Phase 1 is tagged and does not wait for Phase 2.

- [ ] **Step 4: Write the schema**

Create `core/role-schema.md` with exactly this content:

```markdown
# Role Schema

> Required structure for role files.

## File Location

`model/roles/*.md`

A role owns nothing and nothing owns it, so it is a file. A profile holds one by listing it,
which is the only edge that reaches a role from the company's side; a role reaches out to the
skills it requires and to nothing else.

## Frontmatter

| Field | Required | Type | Description |
| --- | --- | --- | --- |
| `source` | Yes | ref → source | Where this page's facts are mastered — the H1 of a file in `sources/` |
| `source-id` | No | string | The identifier this page has in its source — a directory id, a record key. Absent when the source has none, as a repository does not. |
| `requires` | No | array of ref → skill | The skills the seat needs, each the H1 of a file in `skills/`. Absent while nobody has said what the seat needs. |

## Sections

| Section | Required | Description |
| --- | --- | --- |
| `# [Seat]` | Yes | The canonical name of the seat. Profiles reference the role by this exact string. |
| `> [Purpose]` | Yes | Single-line statement of what the seat is for |
| `## What it takes` | Yes | What the holder is handed, and what the seat refuses to start without |
| `## What it produces` | Yes | What leaves the seat, and in what form |
| `## What it never does` | Yes | A list, one sentence each, of what the seat refuses whoever holds it |
| `## References` | No | Table. The documents the seat works by — a rulebook, a mandate; its columns are declared below. |

`## References` is a table with these columns:

| Column | Required | Type | Description |
| --- | --- | --- | --- |
| `What` | Yes | string | The kind of document — a rulebook, a glossary, a mandate |
| `URL` | Yes | string | Where it is |

## Purpose

A role is a seat the company needs filled — one file, named once, held by whichever profile
lists it. It answers "what does this seat take, produce and refuse, and what must whoever holds
it be able to do?" for someone filling it, holding it or handing work to it. It is not a
person's history in the seat, which lives on the profile and in its experiences, and it is not
a process, which says when the seat acts.

## Writing rules

- Person-neutral: no name, employer, date or number from any profile, and never who holds
  the seat. Who holds it is the profile's fact.
- Named for the seat, so a second holder would still be called that: `Owner`, not
  `Entrepreneur`; `Reviewer`, not the reviewer's name.
- Each line under `## What it never does` is a sentence an agent can hold an output against.
  "Never merges" can fail; "acts responsibly" cannot.
- `requires` lists what the seat needs, not what its current holder happens to have.
- A skill the role requires that the holding profile does not claim is a gap the validation
  pass reports, never an error. It says what the holder has to learn or the company has to
  hire, which is information about the person and not a defect in the model.
```

- [ ] **Step 4: Add the check**

In `instanceChecks`, after the object whose `name` is "required frontmatter fields are present" and before the `date` check, insert:

```js
  {
    // R8: a field typed `enum` lists its values at the front of its Description as backticked
    // tokens, and a value written for it is one of them. Two assertions, one per half of the
    // rule. A schema whose enum opens with prose lists nothing, and that is the schema's
    // finding, because a value cannot be held to a list nobody can read; a value outside the
    // list is the error R8 names. The tokens are read from the front of the cell and nowhere
    // else, so a value mentioned later in the sentence is not a permitted value.
    name: "enum values are listed, and written values are among them",
    rule: "R8",
    run() {
      const enums = new Map();
      for (const t of TYPES) {
        const listed = [];
        for (const { field, declared, description } of fieldsOf(t.type)) {
          if (declared !== "enum") continue;
          const leading = description.match(/^((?:`[^`]+`(?:\s*,\s*|\s+or\s+|\s*))+)/)?.[1] ?? "";
          const tokens = [...leading.matchAll(/`([^`]+)`/g)].map((m) => m[1]);
          if (!tokens.length) {
            fail(`${core}/${t.type}-schema.md: \`${field}\` is typed enum and its Description opens with no backticked value; R8 lists the permitted values where a check can read them`);
            continue;
          }
          listed.push({ field, tokens });
        }
        enums.set(t.type, listed);
      }
      walkMd(EX, (child, text) => {
        const type = typeOfFile(child);
        if (!type) return;
        const fmText = frontmatterOf(text);
        for (const { field, tokens } of enums.get(type) ?? [])
          for (const value of fieldValues(fmText, field))
            if (!tokens.includes(value))
              fail(`${child}: \`${field}\` is "${value}", and ${type}-schema.md permits ${tokens.map((t) => `\`${t}\``).join(", ")} (R8)`);
      });
    },
  },
```
