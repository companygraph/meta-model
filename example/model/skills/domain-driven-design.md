# Domain-Driven Design

> Modelling software around the language the business already speaks.

## In practice

Name things as the business names them, and refuse a name that only makes sense inside the
codebase. Draw the boundary between one model and the next, and hold it when a second team
wants to reach across it. Rework the model when the language changes, rather than mapping
around it and keeping both.
